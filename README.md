# eitanalperstein.com

Eitan Alperstein's personal site: code projects, music, math tutoring, The Paw, academics, languages and volunteering.

For the list of content that still needs filling in (photos, recordings, stats…), see **[CONTENT-TODO.md](CONTENT-TODO.md)**.

## How this site works

**Stack.** [Astro](https://astro.build) generating a fully static site (plain HTML/CSS plus small scripts), deployed on Vercel. No database, no server. Fonts are self-hosted via Fontsource; the hero background uses `d3-delaunay`.

**Where things live.**

```
src/data/github-projects.json      code projects synced from GitHub (generated; don't edit)
src/data/projects.overrides.json  display tweaks, ordering, private projects
src/lib/projects.ts               merges the two into the list the site shows
src/data/life.ts         music, tutoring, The Paw, academics, languages, volunteering
src/data/site.ts         email, GitHub/LinkedIn links, profile photo override, "Right now" list
src/pages/               one file per route (index, music, tutoring, the-paw, academics,
                         languages, volunteering, daily-tracker, arduino-parkour, tempo)
src/components/          sections and shared pieces (Nav, Gallery, ComingSoon, Tags, …)
src/layouts/             Layout (html shell), Page (life pages), Showcase (project pages)
src/scripts/             interactive bits: hero Voronoi field, LCD game, guitar strings, Tempo demos
src/scripts/tempo/       Tempo's scoring and quick-add parser, copied from the tempo repo
public/shots/<slot>/     images produced by `npm run shots` (don't edit by hand)
public/media/guitar/     audio files for guitar recordings
public/audio/            spoken name clips (generated by `npm run voices`; own/ holds your recordings)
scripts/shots.mjs        the image pipeline
scripts/sync-projects.mjs  snapshots GitHub repos tagged `portfolio`
.github/workflows/sync-projects.yml  runs that sync daily and deploys changes
scripts/voices.mjs       generates the name clips with macOS text-to-speech
vercel.json              build settings, redirects (incl. subdomain redirects)
```

Pages render from the data files, so most updates are data edits, not markup.

**Common tasks.**

- *Add a code project:* see **How to add a project** below. Usually it's just adding GitHub topics.
- *Add a Paw article:* add to `paw.articles` in `src/data/life.ts` (format in CONTENT-TODO.md).
- *Add photos/screenshots:* put them in `~/dev/screenshots/<slot>/` and run `npm run shots`. Slots are listed in CONTENT-TODO.md; to add a new slot, add its name to `SLOTS` in `scripts/shots.mjs` and render it with `<Gallery slug="<slot>" … />`.
- *Add a guitar recording, testimonial or stat:* see CONTENT-TODO.md.
- *Regenerate the spoken name clips on /languages:* `npm run voices` (macOS; details in CONTENT-TODO.md).

**Run it locally.**

```sh
npm install
npm run dev        # http://localhost:4321
npm run build      # production build into dist/
```

**Branches, previews and deploys.**

- `main` is production: every push to `main` deploys to www.eitanalperstein.com.
- Any other branch gets its own Vercel preview URL on push (shown in the Vercel dashboard and on the GitHub commit). Previews are protected, so you need to be logged into Vercel to view them.
- Normal flow: make changes on a branch → push → check the preview → merge into `main`.
- `vercel.json` redirects `tracker.eitanalperstein.com` → `/daily-tracker`, `parkour.eitanalperstein.com` → `/arduino-parkour` and `tempo.eitanalperstein.com` → `/tempo` (host-based redirects; rewrites would not work because `/` is a real file). All three subdomains are attached to the Vercel project.

## How to add a project

The "Code" section on the homepage builds itself from GitHub. Tag a repo and it shows up; no code to edit.

### A public GitHub repo (the normal case)

1. On the repo's GitHub page, click the ⚙️ next to **About** (top right of the code tab).
2. Fill in:
   - **Description**: becomes the one-line blurb on the site.
   - **Website**: becomes the "Visit" link (leave empty if there's nothing to visit).
   - **Topics**: add the ones below.
3. Wait for the daily sync, or run it now: GitHub → Portfolio repo → **Actions** → **Sync projects from GitHub** → **Run workflow** (on `main`). It commits the change and Vercel deploys it in about a minute.

A "Code" link to the repo is added automatically.

**Topics the site understands:**

| Topic | What it does |
|---|---|
| `portfolio` | **Required.** Puts the repo on the site. Remove it to take the project off. |
| `portfolio-featured` | Shows it as a big featured card at the top of the Code section. |
| `ai` | Adds the "AI" tag (built with AI assistance). |
| `for-students` | Groups it under **For students**. |
| `tools` | Groups it under **Tools I use myself**. (This is also the default if no group topic is set.) |
| `simulation` | Groups it under **Simulations & experiments**. |
| anything else | Shown as a stack tag. Known ones get proper names (`nextjs` → Next.js, `cpp` → C++, `html-css-js` → HTML/CSS/JS, …; the list is `STACK` in `src/lib/projects.ts`); others are title-cased (`signal-processing` → Signal Processing). If a repo has no stack topics, its main GitHub language is shown instead. |

Archived repos, forks and private repos are never shown, even if tagged.

The title comes from the repo name (`tab-teacher` → "Tab Teacher", `SphericalVoronoi` → "Spherical Voronoi"). To use a different title, see overrides below.

### A private project (or anything not on GitHub)

Private repos can't be read publicly, so these are written by hand: add an entry to `"private"` in `src/data/projects.overrides.json`, copying an existing one:

```json
{ "id": "my-app", "title": "My App", "blurb": "One line about it.", "stack": ["Swift"], "url": "https://…", "group": "mine", "ai": false, "date": "2026-07" }
```

`group` is `students`, `mine` or `sims`. `url` can be `null`. `date` is the month you made it (`YYYY-MM`). Private projects never get a "Code" link. Commit and push.

### Changing how a synced project looks: `projects.overrides.json`

- **Order**: within each group, projects are listed newest first by `date`.
- **`repos`**: per-repo overrides keyed by repo name, using the same field names as private entries. Common ones:
  - `"title": "3D Projection"`: a nicer name than the repo's.
  - `"date": "2026-07"`: when you made it, shown on the card and used for ordering. Defaults to the month the GitHub repo was created, so set it when the repo is newer than the project.
  - `"blurb"`, `"stack"`, `"url"`, `"group"`, `"ai"`: replace what GitHub says. For example, `"url": "/daily-tracker"` points Visit at a page on this site instead of the repo's Website.
  - Featured cards: `"hero": 2` sets the card's position (1 = first, the wide one), `"long"` is the longer text on the card, and `"slug"` picks custom artwork (`the-paw`, `tab-teacher`, `spherical-voronoi`, mapped in `src/components/Featured.astro`). Without a slug, a featured card gets generated artwork with its title. For a public repo, the `portfolio-featured` topic decides *whether* it's featured; `hero` only sets the position.

### Running the sync yourself

```sh
npm run sync-projects   # updates src/data/github-projects.json
npm run build           # check it
```

Then commit and push. It uses `GITHUB_TOKEN` or your `gh` login if available, and works without either (GitHub allows 60 unauthenticated requests per hour).

The GitHub Action (`.github/workflows/sync-projects.yml`) runs daily, on demand from the Actions tab, or via a `repository_dispatch` event of type `sync-projects`. It only commits when the list actually changed, only after the site builds successfully, and only on `main`. Runs started on another branch, or with **dry run** ticked, just print what would change.
